# 围猎臭臭

统一辅助器 `Start-Tata.cmd` 左侧新增“围猎臭臭”。按用户提供的刷分流程实现，未将收益视作实测结论。也可运行 `python run.py tata hunting --panel`。先选择游戏窗口，双开时必须明确选择；面板默认“后台运行”，即可继续用其他软件，游戏窗口保持打开且不要最小化。打开面板或“后台只读检查”不会激活或操作游戏；主动点“开始围猎”才取得与主线/钓鱼共用的窗口控制锁，未勾选后台时会激活游戏。

## 当前流程

- 默认1倍场攒到10个锁定；储备数量、低倍倍率（1/2/5）、时长、轮数、保留金猎币及是否用狂暴可设置。
- 低倍场用原背景图识别场地，将实时怪物坐标投影到画面，优先攻击密集怪群中的真实怪物；普通怪同样掉道具，不向空地消耗。默认启用狂暴，等待实际生效再按原游戏射速发射，后台使用窗口消息点击脉冲。补到10个后退出，再切200倍场。
- 200倍场不手动射击、不用狂暴。只在可锁定的活跃萨满臭臭出现、且原游戏最高分选靶规则会选到萨满时点一次锁定。回读实际锁定编号后跟踪该次生成；同编号被回收复用也不能当作旧目标。
- 跟踪目标死亡或离场（不分谁击杀）、锁定切到其他怪、效果结束或达到金币保留阈值时，优先点击已经识别好的退出按钮。有本局奖励时处理奖励页，并等到实际返回选场页。目标消失也可能是自然离场，日志不冒称击杀或奖励归自己。
- 锁定还有存货则继续200倍；耗尽后回低倍补到储备数量。达到轮数/时长上限或点停止时释放鼠标并请求退出。F8、窗口关闭/最小化、鼠标按住时窗口移动/缩放均停止工具输入；前台模式还会在失去前台时停止。游戏自己的锁定可能仍有效，需要手动退出。

场地解锁来自原 `UnlockCost` 与本账号累计获得金猎币。公共配置虽有 `NeedBullet=90000`，用户与本机脚本均实测余额不足90,000也能进入200倍；不把该字段当作钱包入场门槛，只检查足够一次射击及所设保留数量。不会买道具、补货币或点击解锁付费流程。保留数量是触发退出的阈值，游戏已发射/待结算子弹可能使最终余额略低。

## 原逻辑核对

已执行0.50.1原字节码的18项隔离检查，不连接游戏、不发送协议：

- `TrapBattleEnemyData.Init` 将实例 `id`、配置 `cfgId` 分开保存；萨满配置ID是2008。
- `TrapBattleScene.FindBestLockTarget` 从有效、活跃演员中先按 `TrapZobo.Score` 最大选择，同分再按距离。当前萨满分值1500，为配置最高分；锁定按钮按此规则自动选目标。
- `TrapBattleBossTipNode.OnUpdate` 会因演员靠近入场提示点而移除头像；头像消失不代表死亡。
- `TrapBattleModel.OnUnitDead` 对自己或其他玩家击杀都会移除同一实例，演员随后播放死亡/回收。工具读当前实例/演员，不看分数、掉落归属或头像。
- `TrapBattleView.OnBtnCloseClick` 无奖励时直接触发离房；有待领奖励时，离房可能延迟到奖励回调。`BaseRewardView` 接收界面点击开始奖励飞入/关闭动画，不要求寻找不存在的专用按钮。
- 锁定/狂暴道具数来自 `PlayerAssetModel.backpackModel._itemMapRaw` 的30/31项，金猎币来自 `insideModel.insideMap[110008001].amount`，均按原 getter 依赖读取，不用界面缩写猜余额。

原源码也显示锁定会尝试重新选靶，因此不能等倒计时结束才退出。此项与用户的刷分流程一致；刷分收益、击杀概率及长期稳定性没有据此实测。

## 验证与运行

```powershell
# 仅后台读取；不会激活游戏、移动鼠标或发射
python run.py tata hunting --observe --seconds 10

# 独立面板
python run.py tata hunting --panel

# 显式前台模式；先打开围猎选场页或房间并保持前台
python run.py tata hunting --run --activate --stock 10 --low 1 --rounds 10 --seconds 3600

# 后台运行：先列出窗口；将下一行的 <窗口编号> 替换成所选 hwnd（双开必须选）
python run.py tata hunting --list-windows
python run.py tata hunting --run --background --hwnd <窗口编号> --stock 10 --rounds 10 --seconds 3600

# 验收替代目标：2倍场鱼怪臭臭（2002），不手动射击、不用狂暴、不自动刷道具
# 鱼怪必须是当前原游戏最高分目标，才会使用锁定；测试后去掉此参数恢复200倍萨满
python run.py tata hunting --run --test-fish --rounds 1 --seconds 180 --reserve 90000

# 离线原字节码与合成状态/原图回归
python games/tata/hunting/verify_logic.py
python -m unittest discover -s games/tata/hunting -p "test_*.py" -v
```

独立自动CLI运行前可清理上次 `runtime/tata/hunting/STOP`；面板启动会清理旧标记。临时日志、观察状态和布局失败证据留在 `runtime/tata/hunting/runs/<编号>/`，账号仅保存UID哈希，不导出原UID、昵称、令牌或完整内存。原APK资源提取的3张按钮图片与最小公共规则位于 `assets/`；没有玩家截图。

## 本地记录与占用

运行记录全部在被 Git 忽略的 `runtime/tata/hunting/`，不会随提交或推送上传。程序不持续录屏，也不保存完整内存转储。

| 内容 | 位置与保存方式 |
| --- | --- |
| 当前账号任务状态 | `windows/<窗口编号>/status.json`，覆盖写入 |
| 单次任务日志 | `runs/<编号>/events.jsonl` 或监督子目录，追加写入 |
| 布局诊断截图 | 每个任务的 `last-layout.png`，在该任务中覆盖保存最新一张 |
| 异常时的允许字段观测 | `last-observation.json`，覆盖保存 |
| 监督与恢复记录 | `supervised*/<窗口编号>/<任务编号>/`，每次重启建立新目录；`worker.log`还包含一份子进程输出 |
| 本机统计与核对截图 | 本地整理生成，不纳入版本控制 |

2026-11-02双账号夜间运行连同多轮开发验收，围猎目录实测约73 MiB，其中截图约62 MiB，JSONL及进程日志约12 MiB；这不是每小时固定增长量。单次任务截图不逐帧累积，日志、历次运行及重启目录会保留，目前没有自动到期删除策略。

项目的 `runtime/tata/research/` 另存历史解码、配置提取等研究资源，不属于围猎每轮新增缓存；`runtime/tata/mainline/accounts/` 包含账号角色池、备注和布阵，不能把整个 `runtime/` 当作临时截图目录直接清空。清理旧诊断记录前应停止对应任务，并保留需要的统计与失败证据。

## 统计口径

余额起点减终点是净消耗，存在新领取、购买或其他收入时不能直接当作射击总支出。此前围猎事件日志记录了余额、道具和目标跟踪，没有逐次记录个人积分；截图以“万分”显示，只能据此报告约数。每个账号的币量与分数需分别标明起止证据，混合测试、手动和挂机的结果不能冒称脚本独立收益。`completed` 表示跟踪目标结束次数，不等于本人击杀数或得分次数。
