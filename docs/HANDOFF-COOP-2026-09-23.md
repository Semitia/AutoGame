## 核心缺陷（必须接着修）

- 原单人代码本来已有 `finish_pending`、`merge_pair`、`discover`、`choose_buff`、奖励关闭和恢复逻辑。本轮错误地另写简化循环，遗漏这些机制。问题不是用户认为棋盘平移太简单，而是没有复用现成实现。
- `board_cells()` 目前只用于日志，未参与决策；`units` 没有填充；`merge_pair` 仅导入没有调用。完全没有合成，不可把输出坐标当成支持左右棋盘。
- 棋盘格坐标是截图估算，扩格集合不完整；不能盲扫或拖动伙伴半边。参考图中七个初始格为三列两行加上方中间一格，扩格位置仍需验证。
- 使用 `beginner.json` 作为房主默认配置错误。实际选卡文本含安妮/熊、雷电、地鼠等，明显与小炮/骑士/冰法师/雅典娜旧配置不符。`choose_card` 因无匹配经常回退中间项。访客配置同样应核对实际阵容。
- 初始免费召唤与前5次召唤处理已临时补上，但接管中途局仍把 summons 设0，不能作为可靠计数。
- 所谓满格逻辑只是同价格重试后强制强化15秒；它偏离2:1价格策略，未识别满格也未合成腾位。必须移除该替代策略并接回原有棋盘/合成决策。
- 波次/名字等背景OCR在弹窗后仍可读。购买前必须先处理顶层UI，不能因背景价格可读就点击。加强对动作完成与超时的验证，禁止数分钟无效点击。
- 奖励关闭目前固定点(216,628)，强化目前识别文本标题后点三卡之一；只在本轮截图校准，未覆盖所有弹窗。应结合原模板与实际合作UI。
- 设备锁只对同一 runtime 下的合作程序有效，不会排斥旧单人 runner；启动前必须检查控制同一设备的其它进程。
- `--only-side host --battle-only` 虽只给房主提交 worker，仍构造两端 Screen、Reader并获取两端锁，不是完整的单设备入口。
- 没有安全的同局状态持久化/恢复，没有稳定跨局逻辑。异常应保存现场并停止，而非直接重试花费资源。
