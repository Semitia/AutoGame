# 桌面战斗助手

未知阶级救急识别默认开启：主线暂停局接管/修复、合作检查点恢复后，会尝试识别已有英雄的阶级，并按原战术参与合成；不覆盖已知操作记录阶级。无需额外配置，识别可能不准。详情见 `docs/HANDOFF-20260923-HERO-GUI-TIER-VISION.md`，命令行可用 `--no-visual-tiers` 关闭。

双击仓库根目录 **Start-GUI.cmd**，打开「出战准备」。新版采用 **Qt / PySide6**，使用深色卡片布局，替代旧版 Tkinter 表单。日常操作直接在主界面完成，不需要管理配置文件路径。

## 第一次使用

1. 在主界面选择「主线挑战」或「双人合作」。第34关和其他主线关卡一样，直接填写关卡编号。
2. 选择关卡、挑战方式（打一局、连续挑战、清空体力）和最长运行时间。
3. 从下拉框按**模拟器窗口名称**选择设备，例如「MuMu安卓设备 · 实例0」或「MuMu安卓设备-1 · 实例1」，后面附带ADB编号。打开界面即自动发现设备，每5秒更新；切换模式、配置或编辑阵容不会清空列表，也可手动刷新。程序通过MuMu实例信息和实时启动标识核对编号与窗口，不按 `emulator` 编号顺序猜测。名称暂不可用时保留原编号；离线选择标记「未连接」，不自动切换到别的账号。

设备发现只查询 ADB 列表、MuMu 实例名称及 `/proc/sys/kernel/random/boot_id`，不点击游戏、不创建新的ADB连接别名。底层脚本仍接收原始设备编号，显示名称不会混入启动命令。
4. 直接编辑四张英雄卡片：英雄、职责、保留阈值、至少留场数量、选卡顺位、技能优先级。选卡顺位1最高，四位不能重复；技能可拖动排序，越靠上越优先。「技能库 / 收录」双击已有技能即可加入，不必重复输入。更换英雄时恢复该英雄上次编辑的技能顺序；已有阵容保留各自的配置。阵容下方直接调整强化/召唤费用比例。
5. 在同一页面选择开战入口、失败后是否停止，核对游戏实际阵容后「检查配置」并「开始战斗」。检查配置不代表设备或游戏画面已验证。

合作页面上下展示双方四英雄阵容及各自战术，填写双方准确昵称与设备即可。新英雄通过「添加英雄」填写准确名称即可，识别关键词可选，无需编写 JSON。「导入阵容 / 导出」只用于复用或分享已有阵容。

下拉框和整数、小数框即使已获得焦点，也不会因滚轮改值，滚轮传递给外层页面；点击箭头、键盘输入仍可修改。

## 英雄技能库

双击「未认领技能」直接按默认标题认领并加入优先级，不再二次确认。未认领列表直接分行显示标题与完整描述，长描述自动换行；认领后的名称只取标题，即原始识别文字的首个文本段。认领后记录移出此池；战斗再次读到同一段文字不会重复列入。选中「已认领技能」点击「退回未认领」，原始OCR记录恢复到公共候选池，可重新分配给其他英雄，同时从本地各方案该英雄的优先级中移除。正在运行的阵容快照不受影响。旧版已确认记录仅在原始标题与唯一英雄技能完全一致时自动补上关联，其余仍留待认领。

内置阵容及已有配置中的技能自动汇入 `config/hero-skills.sqlite3`，自定义英雄和手动排序也保存在这里，不入 Git。技能库按英雄名共享，阵容内的顺序仍独立保存。「移除」仅移出本阵容优先级，不删除库里的技能。

新版主线和合作脚本在选卡时自动记录读到的完整文字，CLI 启动也会记录，双方进程使用数据库事务避免互相覆盖。打开「技能库 / 收录」即可查看最新记录。文字包含唯一准确英雄名时归到该英雄；无法判断的保留为待认领记录。双击直接认领标题并加入优先级；仅自动收录不会改变战术。未显示在选卡界面、未被 OCR 读到的技能无法收录，也不表示已获取该英雄完整技能表。旧版已在运行的脚本需下次启动后才启用收录。

## 两种模式

| 模式 | 配置与边界 |
| --- | --- |
| 主线挑战 | 对应 `blue_planet`；关卡、阵容、局数/清体力、失败停止；首页开始、空棋盘、暂停接管、状态文件恢复四选一 |
| 双人合作 | 对应 `bilibili_hero_merge_coop`；双方设备、准确昵称、各自阵容、层数、总时限及可选检查点；单侧必须仅接管战斗；仍是单局候选版 |

单人清体力忽略局数，但仍有总时限。合作只开一局，不提供清体力或重开。合作双方昵称不能沿用脚本内置的旧账号默认值。恢复文件仍由现有脚本校验身份、关卡和阵容，GUI 不绕过恢复约束。详细机制参见 [战术说明](TACTICAL-RUNNER.md) 和 [合作说明](../games/bilibili_hero_merge/COOP.md)。

## 本地缓存与多账号

- 字段修改后约 0.5 秒自动保存，未选齐英雄的草稿也可保存。下次打开恢复上次配置和阵容。
- 缓存在 `config/gui.json`，不入 Git。GUI 不改写 `config/local.json`，旧命令行启动器仍按原配置运行。
- 「新建配置」复制当前设置和阵容，可用于大号、小号、合作等，自动分配新的独立运行目录。阵容是各自独立的副本。
- 新版首次读取旧版配置时，从原阵容路径导入实际内容，不覆盖源 JSON。此后直接编辑的阵容随配置缓存保存，无需另存文件。损坏缓存会提示错误并保留原文件。
- 旧「经典34关」配置自动迁移为主线第34关，保留该模式实际使用的四英雄和战术，之后可直接编辑。原命令行脚本保留兼容，不再作为 GUI 的独立模式。
- 一个 GUI 可以启动多个不同设备、不同运行目录的任务。所有 runner 继续使用已有跨进程设备锁；同一物理设备的不同 ADB 别名不能被锁自动识别，请统一序列号。
- 启动时会自动生成独立的阵容快照。之后修改 GUI 配置用于下一次运行，不影响当前任务。停止操作始终指向选中任务启动时的目录，不受当前配置切换影响。

## 低频设置与安装

Python、ADB、MuMuManager、独立运行目录、恢复检查点和停止标记操作统一位于「设置」。首次继承 `config/local.json`，环境未迁移时通常不需要调整。

现有机器已安装 Qt。新机器安装完整 `requirements.txt` 即包含 GUI 依赖；只补装界面可用 `python -m pip install -r requirements-gui.txt`。也可直接 `python gui.py` 启动。启动器按 `AUTOGAME_PYTHON`、`config/local.json`、`.venv` 查找 Python，优先用同目录的 `pythonw.exe` 正常显示界面，无额外 Python 控制台。启动器确认主窗口出现后才退出；启动失败会保留错误提示，异常输出在 `runtime/gui-launch-error.log`。

## 停止和日志

「战斗记录」显示本次 GUI 会话启动的任务、进程退出状态、控制台输出和最近结构化事件。可以切换任务查看日志，或打开运行目录查看完整记录和截图。退出码 0 只表示进程正常退出，不代表战斗胜利。

选中任务后点「停止选中任务」，向该任务目录写入 `STOP`，等待 runner 安全停止。合作停止并不等于游戏暂停。GUI 在任务仍运行时会保留窗口，要求先停止并等待退出，避免丢失控制入口。不会强杀进程。

STOP 会保留；下次启动前查看上次日志，再在设置中「清除当前配置的停止标记」。不要在其他 GUI/终端仍控制该目录时清除它。界面任务列表不恢复上次会话或外部终端进程，但已有设备锁仍会阻止冲突启动。

## 离线验证

```powershell
python -m unittest discover -s tests -p 'test_gui*.py'
python -m unittest discover -s games/bilibili_hero_merge -p 'test_*.py'
```

GUI 测试创建真实 Qt 窗口，验证主界面编辑、保存、模式切换、合作布局与快照隔离；用模拟子进程验证启动/停止，不连接 ADB 或开战。GUI 不改变战斗识别和策略本身的实测边界。
