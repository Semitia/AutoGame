# MuMu 后台刷关：第 34 关、可配置策略

本版入口为 `strategic.py`。`farmer.py` 是第一版基础接口，启动器已切换到新策略。

## 运行

先将游戏留在 **第 34 关“炎山试炼”的选关首页**。

- **Test-One.cmd**：隐藏游戏窗口，测试一局，显示脚本日志。
- **Farm.cmd**：持续刷第 34 关，胜负结算后均继续，首页体力不足 10 即停；不购买、不看广告补充体力。使用 `--until-stamina`，不受局数和总时长限制，识别异常仍停止。
- **Start-Hidden.cmd**：同上，脚本控制台也隐藏。
- **Stop.cmd**：请求停止，显示游戏；战斗中尝试暂停并保存记录。
- **Resume.cmd**：从保存的阵容记录恢复同一局。手动改过阵容或重开过关卡后不能使用此入口。
- **Show-Game.cmd**：只显示游戏，不停止脚本。

不占用桌面鼠标，不要求游戏获得焦点。运行期间不要同时手动操作游戏，否则阵容记录会失去对应。电脑睡眠或模拟器关闭会中断运行。

## 配置：strategy.json

- `next_price_ratio` 比较**下一次强化费 E 与下一次召唤费 S**，不是累计支出。默认 2∶1：E < 2S 时强化；E > 2S 时召唤；相等优先召唤。
- 不够目标动作的钱时等待，首次强化的解锁条件优先满足。
- 海王、剑圣为输出，`keep_if_space: true`，有空格时保留，不主动合成。
- 雪姬、美人鱼的 `reserve: 2` 表示保留上限；超过两个才主动合成，同角色优先合成低阶。实测合成后可能变成其他角色，因此合成后数量可能由 3 变成 1。
- 目标为召唤且满格时，先合成多余控制/辅助，再合成低阶输出腾位；保留数量内的控制/辅助不作为腾位候选。
- 满格且没有任何允许合成的组合时，才暂时转为强化；一对组合未确认成功，不阻止尝试其他组合。
- 每成功召唤 5 次，识别并登记新格子。
- 普通 buff 按 `buff_priority`：海王、剑圣、雪姬、美人鱼。通过卡片文字关键词识别；同角色普通 buff 从左到右，四阶额外技能默认中间。

策略在 `policy.py`，角色名称、用途、保留数量和 buff 关键词都在 JSON。更换组合不需重写消费/合成策略；添加角色需要同步添加 `heroes` 和 `buff_priority` 条目。暂未实现 GUI。

## 状态与识别

ADB 负责安卓内部截图和触摸，MuMu 官方接口隐藏窗口。OpenCV 检测界面/网格，RapidOCR 本地读取价格、角色名称、卡片、结算和体力，不调用收费视觉 API。

召唤成功记录一阶；合成必须同角色、同阶且低于四阶，确认后重新读取角色名称并升阶。未知界面、无法读取费用或无法确认操作时停止，尽可能暂停。单局测试失败后停止，清体力模式失败后返回并继续。

`state.json` 保存阵容和未确认操作；`runs/时间/` 保存日志和截图。文件锁防止多个脚本同时操作。

清体力模式下，角色/操作确认反复失败时进入局部恢复，仍按可用信息强化、召唤和合成已确认单位。修复检查每隔至少 12 秒只点击一个格子，同一格至少间隔 45 秒；补回角色和占位。无法确认阶级的单位记为 0，不参与合成；失败合成涉及的单位也暂时排除。费用读不出时暂缓消费，继续重读和修复。下一局清空旧记录。无法识别的界面和程序异常仍会停止。

## 环境与限制

本机 MuMu 安卓 15、设备 `emulator-5554`、安卓分辨率 **1080×1920**。Windows 窗口位置和大小不影响坐标。Python 用本机 Codex 运行时；依赖和 OCR 模型在 `.deps`，迁移需调整路径。

仍为游戏专用原型：随机阵容不能保证全胜；buff 暂不区分同角色卡片强弱；OCR、战斗特效和新弹窗可能使脚本暂停。网格搜索范围为底排及上方四排。换关卡需采集对应标题模板。

`test_policy.py` 验证单次费用比较、输出保留、控制/辅助保留、低阶优先、四阶上限、满格腾位及替代合成组合。实战结果见 `VALIDATION.md`；单局成功不代表长期成功率。
